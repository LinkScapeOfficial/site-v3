## 1 Purpose and Relationship to Other Documents

This framework defines how LinkScape measures whether it is achieving the change described in I-01 Theory of Change. It names our impact indicators, how we collect data for each, how we establish baselines, and the templates used to report. It is the measurement engine that feeds G-09 Annual Reporting and I-07 Annual Impact Report; program-specific measurement details live in I-04 Program Evaluation and roll up into this framework.

The framework is owned by the PM and reviewed each cycle before reporting. Because LinkScape is a small, youth-led, volunteer team, our measurement discipline favors a few well-collected indicators over many poorly-tracked ones. We would rather report five honest numbers than twenty guessed ones.

> Targets in this document are intentionally left as blank template fields. Owners set them at the start of each measurement cycle; inventing targets here would undermine the honesty this framework is meant to enforce.

## 2 Measurement Principles
1. Tie every indicator to an I-01 outcome — if a metric does not map to an outcome, we do not track it.
1. Prefer evidence we already generate — GitHub activity, event rosters, submission records — over surveys that add participant burden.
1. Protect participants — measurement complies with E-02 Data Privacy; data from minors is minimized and handled per our youth-safety obligations.
1. Report honestly, including misses — a missed target is information, not something to hide; I-07 states shortfalls plainly.
1. Attribute carefully — we distinguish contribution from sole causation, consistent with I-01 Section 7.

## 4 Data Collection Methods

Each indicator draws from a defined source so collection is repeatable and low-burden. The methods below use tools already in our O-05 stack.

| Method | What it captures | Tool | Owner | Notes |
| --- | --- | --- | --- | --- |
| Platform analytics | Releases, forks, stars, contributors, commits | GitHub | PM / CTO | Primary source; passive, no participant burden |
| Event rosters | Attendance, distinct participants, repeat attendance | Notion | PM | Captured at each event |
| Pre/post surveys | Self-reported skill and confidence change | Zoom/Notion forms | Program lead | Fixed scale; anonymized; minor-safe per E-02 |
| Competition records | Entries and standings | Kaggle / organizer | Program lead | Public results where available |
| Alumni check-in | Progression and trajectory | Email / Slack / WeChat | PM | Annual, voluntary, consent-based |
| Partnership log | External collaborations | Notion | Communications Lead | Feeds FC-4 and I-06 |

> Survey data involving minors is collected with the safeguards in E-02 Data Privacy: minimize what is collected, avoid identifying detail, and store under the access controls in S-01. When in doubt, the CFO owns the safety/security escalation path.

## 5 Baseline Approach

LinkScape has operated since December 2022 but has not previously run a formal measurement framework, so most indicators start without a historical baseline. We use a first-cycle baseline model rather than fabricating past figures.
1. First cycle: record the observed value for each indicator and mark it as the baseline in the tables above — no target is judged against a miss in cycle one.
1. Backfill where clean data exists: for platform-derived indicators (BI-1, BI-2, FC-2), reconstruct prior-period values from GitHub history where reliable, and label them as reconstructed.
1. Set targets from cycle two onward: owners set targets relative to the established baseline at the start of each cycle.
1. Re-baseline on definition change: if an indicator's definition changes, reset its baseline and note the break in continuity in I-07.

## 8 Data Quality and Ethics
- Every reported figure must trace to a named source in Section 4 — no untraceable numbers reach I-07.
- Participation data is stored under S-01 access controls; only the PM and leadership access raw survey data.
- Self-reported measures (DT-2) are labeled as such and never presented as objective assessment.
- Where an indicator cannot be reliably collected in a cycle, we report 'not collected' rather than estimate.
- Any measurement activity touching minors' data is reviewed against E-02 before it begins.
